# Table and lobby UX, 2026-09-18

Seven owner requests in one pass. None of them changes a rule; all of
them change what the screen does with the rules it already has. Sibling
of `docs/table-ux-2026-09-11.md`.

---

## §1 The deck picker folds up

**Request:** "In the Choose a Deck window of the lobby, let's make each
section of decks collapsable and they should be collapsed by default."

The picker holds your saved decks, seven precon sets (thirty-two decks)
and a paste box. Open, that is several screens; a player who knows they
want the Ministry starter scrolled past six other sets to reach it.

Every section is now a `<details>` with the section heading as its
`<summary>`, and none of them carries `open`. The headings count what
they hide — "Nosferatu Bloodline (4)" — so a folded panel still says
what is in it.

**Where the open set lives, and why not in the DOM.** A `<details>`
remembers its own state, but a repaint here is `innerHTML =` and
destroys the element: "Save to my decks" repaints the panel with the
picker still open, and the browser's memory would go with it. So the
open keys live in `Shell.deckSectionsOpen` and are written back by a
`toggle` listener, which is the treatment `helpOpenSections` already
gets for the How to Play sections (`loop.ts`). The `toggle` event does
not bubble, so it is wired per section — and since every repaint rebuilds
the elements, the listeners cannot stack up.

**Close moved.** It used to sit in the row beside "Use this list", inside
what is now the paste fold. With every section closed by default that put
the only way out of a modal inside a fold. It is a footer of its own now.

## §2 A die for a bot's deck

**Request:** "For each bot player in the lobby, add a random deck button
next to the choose a deck button for it to randomly pick a precon deck."

A `🎲` beside the deck button, on **AI seats only**. The host's own seat
does not get one: choosing your deck is the one decision on that screen
that is actually yours. A seat a guest joined is not the host's to
change at all, so it has neither control.

Two things it deliberately does:

- **Playable-as-printed precons only.** A New Blood starter is half a
  deck by design and is under p. 14's two minimums. The chooser offers
  them *labelled*, which is a different act from picking one for
  somebody — a random half deck would deal a seat that cannot legally
  play.
- **`Math.random`, not the seeded RNG.** This happens in the lobby,
  before the game exists. Architecture principle 2 is about the engine:
  the deal's seed still reproduces the game from the decks it was handed.
  What is random here is *which deck the owner asked for*, not anything
  the engine then does with it.

It goes through the same `chooseDeck` every other source goes through, so
a random precon is not a special case anywhere downstream (the lobby
broadcast, the deck fingerprint, the save).

## §3 The stage: a band that never resizes

**Request:** "let's make the section for displaying current actions, like
combat, action cards, political actions, etc. a permanent section so the
table isn't constantly adjusting when cards are being played and combats
happen. When nothing is currently being played it can stay empty but keep
its size."

`actionStrip` and `combatStrip` used to render to `""` when their frames
were not on the stack, so the whole table moved down when a card was
played and back up when it resolved — every card, every combat, every
vote. A player following a card with their eyes lost the board under it.

Both now render inside one `.stage` band that is always emitted, with a
`stageidle` filler when there is nothing on the stack. `min-height`, set
to one strip with a card scan in it (86px of scan plus the strip's
padding) — **not** `height`: a four-way vote with a combat under it is
genuinely taller than the floor, and clipping that would cost more than
the jump it saves.

The cost is a strip of empty space through the quiet parts of a turn.
The gain is that nothing else on the screen ever moves.

## §4 The running vote tally

**Request:** "During a political action, add a bar at the top, like when
it's displaying what card is currently being played, except it should
display the current vote counts for all players."

A third strip inside the stage, drawn whenever a referendum frame is on
the stack: the calling card, who called it, the step, the two totals,
which way it is going, and a pill per standing seat with that seat's
for/against.

**It leaks nothing.** Votes are cast openly (p. 28) — who voted, with
what, and which way is public the moment it happens. This is arithmetic
over the log, not information out of it. The same reasoning
`docs/ai-v1-design.md` §3 gives for putting stealth and intercept in
`PlayerView`.

**One source.** It sums `rf.votes`, which *is* the ledger
`resolveReferendum` sums, so the bar and the result cannot drift. And it
makes the same pass test — "more for than against passes; ties fail"
(p. 28) — rather than a second spelling of it.

**What it does not add.** The blood hunt's "additional votes against"
static (Urban Jungle) is counted at the tally and cast by nobody, so
there is no seat to attribute it to. Rather than quietly leave a total
that jumps at the end, a blood hunt's bar names it.

## §5 The allocation dialog

**Request:** "We need to change how point allocation is picked for cards
like Kine Resources Contested. Instead of a huge list of all the
possibilities, let's have it be a little pop-up window that says how many
points can be allocated at the top of it, then there's all the players
listed and a number box next to each of them that can be adjusted. Make
sure it only allows the exact number of points that are available."

The legal-move generator enumerates every legal split — correct, and what
makes the AI and the host validator work, but as a column of buttons it
is dozens of rows of `Allocate: Methuselah 2=3,Methuselah 4=2` read like
a spreadsheet.

**The dialog is built FROM the options and answers WITH one of them.**
`allocationChoices(dp)` gathers the `chooseTerms` options that carry an
`alloc` param into a question: how many points, which recipients, each
one's ceiling, and a map from a normalised split back to **the option id
the engine offered**. Confirm looks that map up. Nothing in the UI ever
constructs an option id.

That single fact is what enforces the owner's "only the exact number of
points": a split that does not total the points has no id, and neither
does one that misses the card's "among **two or more**" or puts a second
point on a location that one point already burns (Revolutionary
Council's caps). The dialog does not know any of those rules and does not
need to — an unenumerated split simply cannot be sent.

**The other half of the choice is not a spinner.** "Choose a Methuselah
AND allocate N among two or more OTHER Methuselahs" (Reckless Agitation)
and "Choose X ready unlocked Anarchs and allocate 2X points"
(Revolutionary Council) each pick something *besides* the split, and the
legal splits differ by what was picked. Options are grouped by that
half — `AllocChoice.key` — and it gets a `<select>`. Changing it throws
the draft away, because a split assembled for one beneficiary is not an
answer for another.

**The boxes do not repaint.** A repaint is `innerHTML =` and would take
the caret out of a box mid-number, so the `input` handler updates the
running total and Confirm's `disabled` in place and only reads the draft
back out of the DOM. Values are clamped on the way *in*: `min`/`max`
constrain a browser's own spinner, not what a keyboard can type.

**A draft belongs to one decision.** `pruneAlloc` clears it when
`dp.seq` moves, for the reason `pruneSelection` clears a card menu: a
stale draft over a fresh decision is not merely out of date, it is a
wrong answer offered as a live one.

## §6 "Download Log"

**Request:** "Edit the 'Download' button to say 'Download Log' instead."

Relabelled; the behaviour is unchanged, and the two now agree. A save is
`history.snapshot()`, which carries the **command log** — opening it
replays every decision of the game from the deal, so the file genuinely
is the game's log. "Download" on its own sat between Save and Load and
read as a third way to do the same thing.

## §7 Turn 1 is announced

**Request:** "When a game starts, the first thing on the Game Log should
be — [player name]s turn 1 — like it shows for all the subsequent turns."

Every turn after the first is announced by the `TurnBegan` the engine
emits in `endTurn` when it rotates the turn frame. The **first** turn
frame is not rotated into — `initialState` builds it — so no emit site
was ever reached for it, and the log opened in the middle of somebody's
turn without saying whose.

`initialState` now seeds that event as the first entry of `eventLog`,
rather than the engine growing a start hook: the frame the event
announces is the one that function has just written, three lines above.
The event changes no resource, so replaying the log for the fuzz's
pool/blood conservation invariant is unaffected.

It names the seat that actually has the turn, which after
`randomSeating` and the first-Methuselah roll (p. 14) is **not** seat 0
of the deck list.

## What this cost

No engine rule changed. Two new view-state fields in the table loop
(`allocOpen`/`allocDraft`/`allocContext`, and `deckSectionsOpen` in the
shell), one seeded event, and one extracted `submitOption` so the dialog
and the bar answer a decision through the same path rather than through
two copies of the busy latch.

Tests: `tests/ui/table-ux-2026-09-18.test.ts` — fourteen, including the
negative space that matters here: no vote bar without a referendum, no
allocation opener on a decision with no allocation in it, and a split
that totals correctly but is not one the engine offered still refused.
